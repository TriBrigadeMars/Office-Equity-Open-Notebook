## Objective
Evaluate bounded installer variants using the modular package graph, benchmark installer sizes, installed footprints, extraction/install durations, automated lifecycle transitions (clean install, in-place upgrade, component repair, uninstallation, offline install), and missing WebView2 runtime recovery behaviors, selecting a preferred variant decision while maintaining strict offline privacy requirements.

## Key Changes Implemented

1. **Installer Experiment Contracts & Types (`src/types/index.ts`, `src/contracts/installer-experiments.ts`)**:
   - Defined 4 bounded installer variants:
     - `monolithic_full_nsis` (Monolithic Single-Binary NSIS Installer): Bundles all 5 components (~380 MB compressed / ~685 MB unpacked). Requires Admin UAC.
     - `core_minimal_nsis_addon` (Core Minimal NSIS + Optional Addon Support): Bundles core required components (~160 MB compressed / ~320 MB unpacked). Decouples optional Docling extraction (~350 MB) into separate addon packages. Supports non-admin per-user install.
     - `web_bootstrapper_stub` (Web Bootstrapper Stub Installer): ~15 MB installer stub downloading components over HTTPS during setup.
     - `portable_zip_per_user` (Per-User Portable Directory / Archive): Zero-install portable archive (~180 MB zip / ~320 MB unpacked). Zero registry writes.
   - Implemented `WebView2ProvisioningPolicy` and `evaluateWebView2Requirement` to detect system WebView2 runtime via Registry key (`HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}`) and manage offline fallback redistributable or silent bootstrapper downloads.
   - Implemented `simulateInstallerLifecycle` to automate verification across clean install, in-place upgrade, component repair/reinstall, uninstallation, offline installation, and missing WebView2 runtime recovery.
   - Implemented composite scoring algorithm (`calculateVariantScore`) balancing Size Efficiency (30%), Install Speed & Ease (25%), Offline & Privacy Compliance (25%), and Lifecycle Reliability (20%).

2. **Installer Variants Benchmark & Deliverables Generator (`scripts/package-installer-variants.js`)**:
   - Built CLI tool that evaluates all 4 installer variants, runs automated lifecycle verification, computes benchmarks, and generates report deliverables under `.artifacts/reports/l5_2/`.

3. **Contract Test Suite (`scripts/tests/test-installer-experiments.js`)**:
   - Validated variant configurations, WebView2 runtime policies, lifecycle transitions (data preservation, shortcut creation, uninstaller registration, hash verification), offline privacy air-gap compliance, and decision matrix generation.

## Preferred Variant Decision & Justification

**Selected Preferred Variant:** `core_minimal_nsis_addon` (Core Minimal Installer + Optional Addon Support)

### Key Decision Reasoning:
1. **58% Size Reduction:** Reduces initial installer download size from 380 MB down to 160 MB (220 MB / 57.89% savings).
2. **Decoupled Heavy Dependencies:** Heavy optional components like the Docling document extraction engine (~350 MB) are separated into downloadable or demand-loaded addon packages.
3. **Non-Admin Per-User Deployment:** Supports installation to user AppData without requiring Windows Administrator (UAC) elevation, accommodating locked enterprise environments.
4. **100% Offline & Privacy Compliant:** Fully supports offline setup without requiring active internet connectivity during installation.
5. **100% Lifecycle Reliability:** All automated checks passed clean (clean install, in-place upgrade, component repair, uninstallation).
6. **User Data Safety:** Application databases and user embeddings in `AppData/DATA_FOLDER` are explicitly preserved across upgrades and uninstalls.
