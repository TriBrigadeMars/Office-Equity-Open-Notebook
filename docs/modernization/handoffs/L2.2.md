# L2.2 Handoff: Build the minimal Rust/Tauri host candidate

## Objective
Build a minimal Rust/Tauri candidate that exercises the host contract while keeping the existing frontend server and Python services.

## Behaviors Preserved
- Service startup order (SurrealDB, API, Worker, Frontend).
- Navigation restriction policy (loopback allowed, file URIs blocked, external links passed to OS).
- Port conflict detection and runtime path verification.
- Logging structured output mapping standard IO.

## Validation Performed
- **BLOCKED-ON-WINDOWS**: The environment lacks `rustc`, `cargo`, and `docker`, preventing mechanical verification (build and tests) of the Rust source code.
- Source files have been updated to output structured JSON logs, adhere to the port conflict recovery contract stub, and parse the JSON contracts in `tests/contract_harness.rs`.
- `npm run build:types` executed to ensure no TypeScript regressions.

## Explicit Decisions
- Rust sources conditionally compile the Windows Job Object API using the `winapi` crate to ensure child process cleanup. Unix relies on process groups.
- `reqwest` and `sysinfo` crates are included to allow implementation of port ownership classification and HTTP health checks.
- Implemented `tokio::process::Command` to manage service execution asynchronously in Tauri v1's setup hook.

## Rollback Status
- No production TypeScript files were altered. The new Rust implementation lives completely isolated inside `src-tauri`.
- The Node.js Electron main process (`main.js` & `preload.js`) remains untouched.
