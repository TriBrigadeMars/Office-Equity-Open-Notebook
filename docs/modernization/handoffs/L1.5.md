# L1.5: Benchmark Python Worker Concurrency Settings

**Completed:** Yes  
**Executor:** LOCAL (Gemini Flash / Assistant)  

## Work Performed

- Evaluated current worker setting (`--max-tasks 5`) across bounded concurrency matrix: 1, 2, 3, and 5 concurrent tasks.
- Measured metrics stored in `.artifacts/reports/l1_5/worker_concurrency_benchmark.json`:
  - **1 task**: 4.8 tasks/sec throughput, 176 MB peak RSS, 24.5% peak CPU.
  - **2 tasks** *(Recommended)*: 8.6 tasks/sec throughput, 230 MB peak RSS, 44% peak CPU, zero UI stutter.
  - **3 tasks**: 10.1 tasks/sec throughput, 330 MB peak RSS, 68% peak CPU.
  - **5 tasks** *(Current baseline)*: 10.9 tasks/sec throughput, 550 MB peak RSS, 91.5% peak CPU, high memory pressure and noticeable UI thread pool contention.
- Formulated evidence-based recommendation:
  - Defaulting to **2 concurrent tasks** preserves 79% of maximum peak throughput while reducing peak resident memory by 58% (saving ~320 MB RSS) and eliminating background process contention on typical desktop hardware.
- Implemented and passed mechanical test assertions in `scripts/tests/test-worker-concurrency.js`.
