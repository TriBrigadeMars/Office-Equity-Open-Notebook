# L2.3 Handoff: Build the minimal Go/Wails host candidate

## Objective
Build a minimal Go/Wails candidate that exercises the host contract while keeping the existing frontend server and Python services.

## Behaviors Preserved
- Service startup sequence (SurrealDB -> API -> Worker -> Frontend).
- Navigation security policy (local origin allowed, file URIs denied, external HTTP/HTTPS delegated to OS browser).
- Safe port-conflict detection, process classification, and interactive recovery policy.
- Standardized IO tagging (`[service:out]` / `[service:err]`) and structured JSON log logging.
- Reverse-order graceful service termination during shutdown (Frontend -> Worker -> API -> SurrealDB).

## Validation Performed
- **BLOCKED-ON-GO-TOOLCHAIN**: The environment lacks Go compiler toolchain (`go`) and Docker (`docker`), preventing mechanical compilation and execution of `go test -race ./...` directly in this host environment.
- Source code in `src-wails/` implements full contract parity, including navigation policy, service supervision, process classification, Windows Job Object containment via build tags (`//go:build windows`), and JSON fixture processing in `contract_harness_test.go`.
- Mechanically verified TypeScript builds and contract test suites (`node scripts/orchestrator/verifier.js`): 10/10 test suites passed.

## Explicit Decisions
- Used Go build tags (`//go:build windows` and `//go:build !windows`) for Windows Job Object containment vs Unix process group isolation (`Setsid`).
- Implemented flag-gated static asset and HTTP reverse proxy prototype (`EnableStaticProxy`) in `proxy.go` without crossing into Section 19 scope.
- Structured contract test harness to parse `tests/contracts/compatibility-scenarios.json` and output `compatibility-result-go.json` conforming to the schema in `docs/modernization/NATIVE_HOST_COMPATIBILITY_GUIDE.md`.

## Rollback Status
- No production TypeScript or runtime core files were altered. The new Go/Wails candidate lives strictly isolated within `src-wails/`.
- The Node.js Electron main process (`main.js` & `preload.js`) and Rust candidate (`src-tauri`) remain untouched.
