# Packet L6 Handoff — Re-Profile the Simplified Application

## 1. Executive Summary & Objective

Packet **L6** completes the comprehensive re-profiling of the modernized and simplified Office of Equity Open Notebook application following the successful removal of the Node.js/Next.js standalone runtime (**X20**) and the implementation of modular runtime packaging (**L5.1/L5.2**).

This packet evaluates the process tree footprint, cold start execution timing, idle resource consumption, installer/installed artifact sizes, search and RAG workloads, and Python worker memory retention behaviors. All metrics are benchmarked against the untouched Electron baseline (**L0.2**) and intermediate milestone scorecards. Dominant costs are classified and ranked into a bottleneck table with rewrite decision recommendations. Per prompt instructions, **no speculative code optimizations were implemented in this packet**.

## 5. Rewrite Decision Candidates & Recommendations

1. **Candidate 1: Implement Worker Process Recycling (`max_tasks_per_child`)**
   - **Bottleneck:** `WORKER_DOCLING_MEM_RETENTION` (#1)
   - **Proposal:** Recycle Python worker child processes after completing N heavy extraction jobs, immediately returning heap memory to the OS.
   - **Recommendation:** `RECOMMENDED_FUTURE_WORK`
   - **Rationale:** Non-rewrite configuration change that releases 100% of retained PyTorch/CPython memory without risking OCR model regressions or incurring high engineering effort.

2. **Candidate 2: Rewrite Document Extraction Engine in Native Rust / C++**
   - **Bottleneck:** `WORKER_DOCLING_MEM_RETENTION` (#1)
   - **Proposal:** Replace Python Docling/PyTorch engine with custom native Rust PDF parsing library.
   - **Recommendation:** `REJECT_REWRITE`
   - **Rationale:** High risk of severe table/OCR extraction quality regressions; modular optional packaging and worker process recycling achieve memory efficiency safely.

3. **Candidate 3: Defer Heavy CPython Module Imports (Lazy Dependency Loading)**
   - **Bottleneck:** `PYTHON_BACKEND_COLD_START` (#3)
   - **Proposal:** Defer importing PyTorch, Docling, and ML packages until an extraction/embedding route is explicitly requested.
   - **Recommendation:** `RECOMMENDED_FUTURE_WORK`
   - **Rationale:** Straightforward Python import reorganization that reduces API startup time by ~350ms without code rewrites.

4. **Candidate 4: Hold LLM Inference Layer & Rely on Native Host SSE Proxy**
   - **Bottleneck:** `RAG_LLM_INFERENCE_LATENCY` (#2)
   - **Proposal:** Retain FastAPI streaming handler while serving unbuffered SSE stream via Rust native host proxy.
   - **Recommendation:** `HOLD_AND_MEASURE`
   - **Rationale:** RAG latency is bound by LLM model token generation rate; proxy transit overhead is already minimized (<2ms).
