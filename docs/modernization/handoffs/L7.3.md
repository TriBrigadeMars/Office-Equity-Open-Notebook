# Packet L7.3 Handoff — Integrate a C/C++ leaf only when an established native library warrants it (Dependency/Risk Note)

## Executive Summary
Packet **L7.3** evaluates integrating a C/C++ native leaf wrapper for an unavoidable or established native library use case. Per packet specifications and Master Plan Section 29 (Workstream 21), this packet is explicitly dependent on **L6 profiling identifying a qualifying hotspot** or an approved native library requirement where memory safety, ABI stability, and FFI surface trade-offs justify the native integration.

Based on the **L6 Re-Profile the Simplified Application** scorecard (`docs/modernization/handoffs/L6.md`), **L7.1** (`docs/modernization/handoffs/L7.1.md`), and **L7.2** (`docs/modernization/handoffs/L7.2.md`), **no pure Python CPU or allocation leaf hotspots or approved native C/C++ library requirements were identified**. Consequently, this packet executes a controlled rejection/skip decision, preserving 100% Python/Tauri fallback behavior without introducing unnecessary memory-safety risks, ABI instabilities, or C/C++ native build complexity.

---

## 1. Analysis of L6 Profiling & Native Library Requirements

The L6 benchmark scorecard classified the top application bottlenecks as follows:
1. **`WORKER_DOCLING_MEM_RETENTION`**: Post-job CPython heap retention (~620 MB RSS) in the background worker due to PyTorch/Docling tensor caching and PyMalloc fragmentation.
   - *Evaluation:* Memory retention cannot be cured by wrapping a C/C++ leaf. L6 recommended worker process recycling (`max_tasks_per_child`), which reclaims 100% of memory safely.
2. **`RAG_LLM_INFERENCE_LATENCY`**: Network I/O and external model provider inference time (1,650 ms P95).
   - *Evaluation:* Inference latency is bound by LLM token generation rate; native host SSE proxy overhead is already <2 ms.
3. **`PYTHON_BACKEND_COLD_START`**: CPython runtime startup and heavy package imports (~650 ms).
   - *Evaluation:* Import-bound startup cost; recommended fix is lazy module loading, not native FFI extension.
4. **`VECTOR_DB_DISK_LOOKUP`**: SurrealDB HNSW index disk lookups (42 ms).
5. **`DOCLING_PACKAGE_SIZE`**: Disk footprint for optional PyTorch/Docling wheels (+350 MB).

## 2. C/C++ Native Wrapper Candidates & FFI Safety Analysis

Two potential native library use cases were evaluated for C/C++ FFI wrapper feasibility:

| Candidate Native Wrapper | Target Function | Python Baseline Latency | Estimated C/C++ Exec | FFI Transit Overhead | Net Speedup | Packaging Impact | Decision |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **PDFium C-API Extraction Leaf** | `c_extract_pdf_page_text` | 310.0 ms | 290.0 ms | 12.0 ms | +2.5% | +24.0 MB | **REJECT_REWRITE** |
| **Tesseract C-API OCR Image Leaf** | `c_process_image_ocr` | 420.0 ms | 405.0 ms | 15.0 ms | +0.0% | +35.0 MB | **REJECT_REWRITE** |

### Frozen Input/Output Contracts Evaluated
1. **PDFium Leaf:** `c_extract_pdf_page_text(const char* pdf_path, int32_t page_index, uint32_t flags) -> (int32_t status_code, char** out_text_buffer, size_t* out_length)`
2. **Tesseract Leaf:** `c_process_image_ocr(const uint8_t* image_bytes, size_t byte_length, const char* lang) -> (int32_t status_code, char** out_hocr_xml)`

### Safety & Audit Risks:
- **Buffer & Memory Management:** Direct C raw pointer allocation (`char**`) requires manual lifecycle management and risks use-after-free, double-free, or memory leaks on malformed binary streams.
- **Sanitizer Toolchain Availability:** AddressSanitizer (ASan) and UndefinedBehaviorSanitizer (UBSan) are unavailable in the standard execution runner environment.
- **ABI & Process Instability:** Unhandled segfaults in native C/C++ libraries will crash the worker process tree, breaking the crash-isolation contract provided by Python/Tauri.
